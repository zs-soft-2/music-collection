# Verification setup

Project-owned (not synced by zs-kit). Read by `speckit-issue-sync`, `speckit-issue-analyze` and
`speckit-issue-verify`. Generated by `zs-kit init`, filled in for this repo.

## Test levels

The level names are the verification methods an acceptance criterion can use (plus `manual`).

| Level | Files | Run one file | Full suite | Shared environment |
|---|---|---|---|---|
| `unit` | `apps/music-collection/**/*.spec.ts`, `libs/**/*.spec.ts` (jest, per Nx project) | `npx nx test <project> --testFile=<path>` | `npx nx run-many -t test --exclude=firestore-rules,functions` | no |
| `functions` | `apps/functions/src/*.spec.ts` (jest) | `npx nx test functions --testFile=<path>` | `npx nx test functions` | no |
| `rules` | `apps/firestore-rules/**/*.spec.ts` (jest, Firestore emulator) | — (the suite runs inside `firebase emulators:exec`) | `npm run test:rules` | no — the `demo-music-collection` emulator project |
| `e2e` | `apps/music-collection-e2e/src/e2e/*.cy.ts` (Cypress) | `npx nx e2e music-collection-e2e --spec=<file>` | `npx nx e2e music-collection-e2e` | yes — `nx serve` talks to the dev Firebase project's data and deployed callables |

The functions are their own npm project and do not see `libs/`: type-check them with
`npx tsc -p apps/functions/tsconfig.app.json --noEmit`, not the empty `tsconfig.json`.

## Environments

- Locally: `npm start` serves the app on `http://127.0.0.1:4200` (use `127.0.0.1`, not `localhost`:
  another app may hold that). It reads the **dev** Firebase project (`music-collection-16676`) and calls
  the callables deployed there, so a callable whose shape changed needs a deploy before the client works.
- App Check is enforced on dev Firestore: bring the debug token down once
  (`tofu -chdir=infra/environments/dev output -raw app_check_debug_token > .app-check-debug-token`),
  or the pages stay empty in a headless browser.
- Log in with a Google account; admin rights come from `tools/sync/grant-permissions.mjs`.
- Touch a shared or deployed environment only with the maintainer's go-ahead: `firebase deploy`,
  `npm run deploy:*`, `tofu apply`, and every `tools/` script run with `--confirm` (most of them write
  to dev or prod Firestore; without `--confirm` they are a dry run).
